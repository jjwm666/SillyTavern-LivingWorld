# 架构说明

## 目标

Living World 将一次聊天轮次视为一次世界推演机会。系统必须同时满足人物自主性、地理一致性、可验证随机性、信息差与大规模运行成本之间的平衡。

## 一轮推演

```text
主 AI 回复完成
  → 固定本轮消息与生成前世界基线
  → 从旧状态构造每个核心 NPC 的有限认知视图
  → 后台 API 一次性返回 NPC、势力和事件的“意图”
  → 本地规则校验意图；缺失或不合法时使用效用决策补充
  → 本地种子骰子结算移动、计划、势力、事件、风声、经济与背景地区
  → 保存新状态、骰点记录和本轮检查点
  → 构建下一轮公开世界快照并设置酒馆 extension prompt
```

模型不能直接修改状态数值。它只能返回白名单行动、目标 ID、候选事件和叙事摘要。所有 ID、位置、资源、行动条件和判定结果由内核重新检查。

## 人物

核心 NPC 包含长期目标、即时需求、人格、情绪、关系、私人记忆、秘密、日程和当前计划。`buildDirectorBrief()` 为每个人生成不同的认知视图，只包含所在地、已知风声、私人记忆和公开关系。

核心层规模由设置 `coreNpcLimit` 决定（存档上限 `NPC_HARD_LIMIT = 400`），但一次推演请求不会把所有人塞进去：`selectBriefNpcs()` 按「正文提到 → 与玩家同地 → 其余按轮次轮转」挑选 `briefNpcLimit`（默认 48，8–240）份简报，`brief.coreNpcTotal` 仍报告真实总数。未被挑中的人物不在提示词里，但 `evolveWorld()` 仍然会用 `heuristicProposal()` 的本地意图让他们照常行动，因此核心层开大只增加本地计算量，不增加接口成本。

后台 API 未返回某个 NPC 的意图时，本地效用决策仍会给出行动，保证人物不会因一次缺字段而停摆。

## 地图

地图是带权无向图。节点保存控制势力、危险、资源、繁荣和背景人口；边保存距离与地形。旅行只能前往相邻节点，风声也只能经边扩散。SVG 地图只是该图的视图，不是模拟事实来源。

## 势力

### 层级

势力分为四级：`hegemon` 一级、`great` 二级、`regional` 三级、`local` 四级（界面显示纯数字层级，避免把特定世界观的称谓套到其他卡片上）。层级由资源规模推导（设计者可在存档里直接指定），决定派系数量区间、首领默认权威与行动加成。每轮结束的 `settleFactionHierarchy()` 会按资源均值判断升格或降格，并结算宗主—附庸：宗主每轮从附庸抽取贡赋，附庸借宗主之势提升权威。

### 关系维度

两个势力之间不再只有一个标量，而是五个维度：信任 `trust`、利益 `interest`、文化 `culture`、恐惧 `fear`、敌意 `hostility`。

```text
对外关系值 = trust + (interest - 50) * 0.5 + (culture - 50) * 0.3 + (fear - 50) * 0.2 - hostility
```

因此「利益很高但敌意也很高」可以同时成立。这种矛盾组合由 `computeRelationTension()` 量化为张力，供导演层生成阳奉阴违、互相利用、暗中下手的剧情。旧存档的单值关系迁移时会无损映射到维度（正面值进信任、负面值进敌意），再按公式还原出同一个数值。

### 内部派系

每个势力内部有 2–4 个派系，诉求取自扩张、通商、守成、复仇、清议。派系有两种来源：引擎按确定性种子生成的 `origin: 'local'`（保证任何存档都有内容），以及世界模型在推演中通过 `factionClans` 提出的 `origin: 'api'`。后者由 `mergeProposedClans()` 处理：同名归并、超过 `FACTION_TIERS[tier].clanRange[1] + 1` 上限的提案直接拒绝、记录 `createdRound`，并留下一条「某势力内部浮现新的派系」的公开日志。关闭 `aiClans` 即只用引擎派系。初始化时角色卡的世界书条目会一并进入材料，因此派系名可以真的来自设定本身。首领每轮只执行一个主要行动，`settleClans()` 按「该行动是否顺应该派系诉求」结算：顺应者满意度与实力上升，违背者下降，并留下派系注记。满足多数派系时首领权威上升，得罪多数时下降。

势力稳定度不再是独立漂移的数字，而是派生量：

```text
稳定度 = 首领权威 * 0.45 + 派系平均满意度 * 0.3 + 内部团结度 * 0.25
团结度 = 60 - 派系实力落差 * 0.35 - 满意度落差 * 0.25
```

`consolidate` 的意义因此变成「压住内部不满」：它不再是给稳定度加数字，而是让主张守成的派系得到满足，从而经派生公式抬高稳定度。内部张力过高时，系统会直接生成一个派系反弹的剧情钩子。

### 行动

扩张会改变地图控制权并损害原控制者关系；贸易和援助改善关系与资源；施压和阴谋制造事件与宿怨。模型可以返回 `relationDelta`，按维度精细调整关系（允许矛盾组合），本地会做白名单与幅度校验。

## 风声

风声有四层，取自 `RUMOR_SCOPES`：

| 层级 | 传播加值 | 最大扩散地区 | 衰减 | 说明 |
| --- | --- | --- | --- | --- |
| 官方通告 `official` | +3 | 9 | 0.5 | 可信、传得快，可被正文当作公开说法引用 |
| 区域消息 `regional` | +1 | 4 | 1 | 基本出不了本地 |
| 小道消息 `street` | 0 | 6 | 1.5 | 真假难辨，容易被人加工 |
| 密闻 `secret` | -2 | 1 | 2.5 | 几乎不扩散，只在小圈子内流传 |

传播时 `spreadRumors()` 使用 `intensity - 2 + scope.spread` 作为修正，且只有在已到达地区数小于 `reach` 时才继续扩散；衰减按 `scope.decay` 累积进 `decayCarry`，每轮取整扣减强度。小道消息传到 5 个以上地区且强度 ≥ 3 时会自动升级为区域消息并记录，这样「传开了」本身成为剧情事件。层级与 `reach` 可以由推演提出，也可以在世界编辑器里单独修改。

## 编年纪要与压缩

长局最大的敌人是注入体积。压缩只看**成功推演的轮次**（`evolutionCount`，重 roll 不增加）：

- 每 `compressEvery`（默认 12）次推演，把 `compressKeepRounds` 之前的轮次按轮汇总成一条一级纪要，原始日志移出活动日志（仍留在存档与检查点里）。
- 每 `compressTier2Every`（默认 5）条一级纪要合并成一条二级「辑要」，每 `compressTier3Every` 条二级合并成一条三级「纪年」。

`maybeCompress()` 只在 `evolutionCount % compressEvery === 0` 时触发，并用 `compressedThrough()` 判断窗口，因此重复调用不会产生重复条目。压缩只读取 `logs`（活动日志），不读写检查点，所以重 roll、Swipe 与回滚逻辑完全不受影响。注入时 `chronicleSummary()` 按三级→二级→一级的顺序取条目，形成「编年纪要」一节。

## 日常与节令

`settleDailyLife()` 每轮挑 `dailyActors` 个人物（优先玩家所在地）过日常：不掷骰，只写 `routine`、微调情绪并留下 `type: 'daily'` 的日志。节庆由 `resolveFestivals()` 合并三类来源——内置 `DEFAULT_FESTIVALS`、存档里的 `festivals`（初始化时世界模型依据角色卡与世界书写入的为 `origin: 'worldbook'`）、设置页手写自定义（`名称|月-日|描述`）。日期命中时 `settleFestivals()` 调整全区繁荣、动荡与物价，并让核心人物情绪上扬，留下 `type: 'festival'` 的公开记录。

## 骰子

`SeededRandom` 从世界种子、轮次与判定序号派生随机序列。每次 d20 判定保存公式、原值、修正、难度、结果和种子。相同状态与相同意图可复现相同结果。

## 规模

- 核心层：重要 NPC 逐人决定意图并逐人判定。
- 势力层：每个活跃势力每轮最多执行一个主要行动。
- 背景层：按地区聚合人口、动荡和繁荣，以地区级判定近似大量背景人物活动。

## 存储与重 roll

世界 JSON 优先写入当前聊天的 `chatMetadata`，并备份到 IndexedDB。设置写入 `extensionSettings`，自定义 API Key 不进入世界存档。

### 版本与迁移

当前 `schemaVersion: 3`。v1 → v2 补齐派系、层级、权威与关系维度；v2 → v3 补齐风声层级/范围、编年体、节庆与人物日常。每一步都只补缺失字段、保留已有数据，重复执行结果一致。

世界状态带 `schemaVersion`（当前为 2）。加载时先看版本：比插件更新的存档直接拒绝（避免用旧规则解释新结构），更旧的存档走 `src/engine/migrations.js` 的迁移链。

迁移有三条硬约束：

1. **幂等**：每一步只补缺失字段（`if (!faction.clans) ...`），重复执行不会重新生成派系、也不会叠加数值。
2. **不丢数据**：迁移只增不改，原有字段——包括插件不认识的字段——原样保留；关系值经维度往返后仍是同一个数。
3. **不影响回滚**：检查点里的 `before` 与 `state` 走同一个迁移函数，因此旧存档的 Swipe 基线、删除楼层回滚都能继续工作。

### 基线

每次正式生成前记录世界基线。生成结束后，以基线和本轮最终文本推演，因此同一楼层的新 Swipe 不会在上一次结果上再叠加一次。删除最近已推演楼层时，恢复到仍然可见的最新检查点。切换聊天会中止旧请求并重新加载对应存档。

## 注入

`buildWorldContext()` 生成的是 `<living_world>` 包裹的两段结构：

- 【世界档案｜既定事实】：只陈述事实（局势、势力格局、内部矛盾、人物状态、风声、骰点转折），不写指令口吻的祈使句。
- 【写作要求】：明确要求主模型把这些事实当作已发生的事写进正文、每轮至少体现两条势力动向、秘密只能暗示、不要念出数字、不要提「引擎／系统／推演」。

默认按**正文焦点**收窄：`buildFocus()` 以玩家所在地区为种子，扫描最近对话里出现的 NPC 名与地名，把这些人、他们所在的势力与首领纳入焦点，再按 `focusNpcLimit` / `focusFactionLimit` 截断。焦点之外的人依然在全量推演，只是不注入，避免长局后注入退化成与正文无关的资料库。风声按层级分组输出并各自标注可信度，压缩后的旧事以「编年纪要」出现。

注入位置与深度可配置（0–8），也可以关掉写作要求段落——真实测试中主模型若完全不理解注入内容，把深度设为 0 并关闭写作要求是最快的排障方式。

## 图谱交互（地图 / 人物关系图 / 势力图）

三种图谱共用一套视口实现：SVG 使用固定 `viewBox`，缩放与平移写在内部 `<g data-lw-viewport>` 的 `transform` 上，拖动时不重绘、不丢失选中状态。容器带 `data-lw-pan-zoom="map|people|factions"`，`panel.viewStates[key]` 分别保存各自的 `{ scale, x, y }`（`normalizeMapView` clamp 到 0.4×–4×），因此切换页签不会互相影响。

- 滚轮：以指针为锚点缩放（`Math.exp(-deltaY * 0.0015)`）。
- 拖动：单指/鼠标按住空白处平移（节点与按钮不触发平移，保证点击可用）。
- 双指：`pointerdown` 记录多指，两指时进入 pinch，按指距比例缩放并保持两指中点为锚点。
- 双击：复位到 `{ scale: 1, x: 0, y: 0 }`；`view-zoom-in/out/reset` 按钮走同一条 `setViewScale` 路径。
- 人物关系图点节点只改变「中心人物」（`peopleFocusId`），打开名片走侧栏的「人物名片」按钮，所以点击不会突然跳走。

## 界面主题与地图风格

面板根节点用 `data-theme` 切换观感，取值 `dark` / `light` / `glass`。

- `glass`（液态玻璃）由三组 CSS 变量驱动：`--lw-glass-alpha`（用户设置的透明度，15%–95%）、`--lw-glass-strong`（alpha + 0.18，用于外壳与底色）、`--lw-glass-soft`（alpha × 0.55，用于次级表面），模糊半径 `--lw-glass-blur` 由 alpha 推导（10–35px）。`LivingWorldPanel.applyAppearance()` 负责把这三个数值写到根节点；所有半透明表面都读这几个变量，因此拖动一次设置就能整体变透/变实。
- 玻璃主题只做视觉覆盖，不改布局、不改折叠与视口逻辑；默认主题仍是 `dark`。

地图风格 `settings.mapStyle`：`auto` / `atlas` / `dark`。

- `auto` 在世界层用深色星图，`scope.path.length > 0`（次级及更深）时用 `atlas`。
- `atlas` 的底图由 `views.js` 的 `cityFabric(seedText, depth)` 生成：用 `mulberry32(hashNumber('atlas:' + seed))` 播种，画水系、运河、街区矩形、分级道路、巷弄与桥梁；同一区域每次渲染结果完全一致。层级越深 `detail` 越高，街区越细。
- 面包屑右侧的 `data-lw-action="map-style"` 按钮临时切换风格（`panel.mapStyleMode`），不写回设置。

## 关系连线的表达

三张图的连线都用内联 `style` 指定 `stroke` 与 `stroke-width`（class 只保留虚线与图例语义，避免主题 CSS 覆盖宽度）：

- 势力关系：强度 = |关系值| + 张力 × 0.6，宽度 `1.5 + 强度 / 16`；合作 `#4fd1a5`、冲突 `#ef7568`、中立 `#9db2ac`；|关系值| ≥ 35 时追加一层 `stroke-opacity: 0.14` 的加粗光晕。
- 人物关系：宽度 `1.4 + |信任| / 14`，按温暖 / 敌意 / 中性着色，焦点连线不透明度 0.95。
- 地图路线：按距离 `1.8–4.6`（制图风）/ `2.4–5.2`（星图）分级。

## 折叠区块（`<details class="lw-fold">`）

数值密集或次要的内容统一用 `fold(title, body, { open, hint, key })` 渲染成 `<details class="lw-fold" data-fold-key="…">`：摘要行给出标题与关键数字，展开后才是明细。已经折叠的视图包括概览四块、生涯四块、地图侧栏、事件与风声、骰点说明与列表、设置页每一节、人物名片的每一块。

- `key` 缺省取标题文本，必须在一个视图内唯一且稳定；`panel.folds`（`Map`）保存每个 key 的展开状态，`render()` 结束后 `applyFoldState()` 按 key 还原，所以切页签、推进一轮、筛骰点都不会把用户的选择重置。
- `panel.handleFoldToggle` 用捕获阶段监听 `toggle` 事件写回状态（`toggle` 不冒泡，捕获阶段可以接到）。
- 折叠标题里的按钮（「推进一轮」「打开地图」等）会 `preventDefault()`，避免点击按钮同时收起面板。
- 设置页的表单字段即使处在收起的 `<details>` 里仍然参与 `FormData` 提交（未加 `disabled`），因此收起不会影响保存。

## 就地修改（点一下就能改）

设置页曾有一个「用户世界编辑器」，把整个世界序列化成 JSON 让人手改；字段一多就没法用，也容易改坏。现在改成「在哪看见就点哪里改」。

- 视图侧：`views.js` 的 `editable(kind, id, path, text, { type, value, label })` 输出 `<span class="lw-editable" data-lw-edit="kind:id:path:type" data-lw-value="…">`。`type` 为 `number` / `text` / `textarea`；`value` 用于显示被格式化过的数字（如 `1,200`），编辑框里拿到的是原始值。
- 面板侧：`panel.handleClick` 最先检查 `[data-lw-edit]`（先于 `[data-lw-action]`，因此可以安全地放在按钮内部），`beginInlineEdit` 把节点内容原地换成 `<input>` / `<textarea>`；回车保存（多行用 ⌘/Ctrl+Enter）、Esc 取消、单行失焦即保存、多行有「保存 / 取消」。提交后节点会带上 `data-edit-settled` 时间戳，避免冒泡回来的同一次点击又打开编辑器；`render()` 开头统一 `cancelInlineEdit()`。
- 引擎侧：`src/engine/edits.js` 是唯一写入入口。`parseEditSpec` 解析四段式描述，`resolveEditTarget` 按 kind（`world` / `player` / `region` / `npc` / `faction` / `clan` / `event` / `rumor`）取对象，区域用递归查找所以次级、再次级区域同样可改；`coerceEditValue` 按 `EDIT_LIMITS` 夹取数值（繁荣 0–100、动荡 0–100、物价 20–400、天气强度 0–3、权威 0–100、三项资源 0–100、人心/势力 0–100、优先级 1–5、声誉 −100–100 等），文字去掉多余空白并截断到 600 字，空值与非法数字直接返回错误。路径支持数组下标（`goals.0.description`）。
- 写回后：`applyWorldEdit` 会为势力与内部派系调用 `refreshFactionDerived`，因此改权威、人心、势力会立即反映到稳定度、团结度与暗涌；`index.editWorldField` 再走 `normalizeWorld` → `store.save` → `refreshInjection` → `panel.setData`，改完即存盘、即生效、即进入下一轮注入。失败时不写档案，面板提示「已保留原值」。

## 安全

- UI 对模型文本进行 HTML 转义。
- 自定义接口只接受 HTTPS，开发本机可使用 HTTP。
- 所有模型 JSON 经过解析、字段白名单、长度限制和状态规范化。
- 默认注入不包含 NPC 秘密、私人计划和未公开风声。
